# Habits ワークフロー定義

> 開発前の下準備ドキュメント。「このアプリを何のために・どう使うか」を先に固定し、
> 機能追加が手段の目的化に陥らないための基準点とする。

---

## このアプリで達成したい状態

毎日このアプリを開き、生活習慣（筋トレ・読書・プログラミング・英語）を
「できた / できてない」で記録し、**どれだけ続いているか** を可視化する。
継続が目に見えることで「途切れさせたくない」という動機を生み、習慣を定着させる。

主役となる指標：**連続日数（ストリーク）**。
（達成率の推移グラフは第2段階として後から追加する。）

---

## 前提

- 起動 = いきなりダッシュボード（ログインなし。認証はバックエンド化の時に後回し）
- 1日に複数回開く。朝・日中・夜で開く目的が違う
- データは端末ローカル（localStorage）、利用者は自分1人

---

## 時間帯別ワークフロー

### 朝（起床後・その日の最初の起動）
1. アプリを開く
2. ダッシュボード最上部で「現在の連続日数」を見る（例：7日連続）→ 途切れさせたくない動機づけ
3. 「今日のタスク」を確認する
4. すでにこなしたものにチェックを付ける

### 日中（確認したい時）
1. アプリを開く
2. 今日の残り / 済みをダッシュボードで確認
3. こなしたタスクにチェックを付ける

### 夜（1日の締め）
1. アプリを開く
2. その日の達成度（ドーナツ）を見て1日を締める
3. 全部こなせていれば → その日が「達成日」になり、連続日数が翌日に繋がる

---

## ストリーク（連続日数）の定義 ※確定

- **達成日** = その日に表示された全タスクにチェックが付いた日
- **連続日数** = 「達成日」が途切れずに続いている日数
- 1つでも未チェックのまま日付が変わると、**連続日数は 0 にリセット**

厳しい定義（1日でも落としたら0）で確定。
緩和ルール（週1回までセーフ等）は将来の検討余地として残すが、現時点では入れない。

---

## 画面構成（ダッシュボード・上から）

1. ストリーク表示（主役）：「🔥 N日連続」
2. 今日の達成度ドーナツ（既存）
3. 今日のタスク一覧 + チェック（既存）
4. （将来）達成率の推移グラフ ← 指標2をここに後付け

---

## このワークフロー実現に必要な新規実装

既存のデータモデル（Task / DoneRecord）は変更不要。DoneRecord に日付があるため過去日を遡れる。

- [ ] 「ある日が達成日か」を判定する関数（全対象タスクが done か）— storage.ts
- [ ] 過去日を遡って「連続達成日数」を数える関数 — storage.ts
- [ ] ストリークを表示する UI — App.tsx

---

## 将来の検討余地（今はやらない）

- 達成率の推移グラフ（指標2 = 積み上げの2段目）
- ストリークの緩和ルール（週1セーフ等）
- ログイン / 認証（バックエンド化のタイミングで）
- Laravel + DB バックエンド化
- タスクの画面上での追加・編集

## 図（workflow.drawio）との対応 ※重要

`workflow.drawio` には **最終的な将来像** も描かれている。
図と現スコープの差分を明示しておく（後から図だけ見て混乱しないため）。

| 図に描かれている要素 | 現スコープでの扱い |
|----------------------|--------------------|
| 各ページ起点の「ログイン」 | **今は無し**。起動＝ダッシュボード直行。認証はバックエンド化の時 |
| 夜「次の日のタスクを考える / タスクを追加する」 | **今は無し**。固定習慣トラッカーなので、日々タスクを足さない。ストリーク定義（全部やった＝達成日）と矛盾するため将来も慎重に |

→ 図のうち **今作るのは「朝ページの、ダッシュボード遷移以降の流れ」が中心**。
   日中・夜ページは、その確認と締めにあたる。
